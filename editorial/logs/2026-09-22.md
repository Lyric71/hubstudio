## Mistake made by this run, and the recovery

While updating `schedule.csv` I first rewrote it with PowerShell `Export-Csv`,
which re-quoted all 49 rows and produced a 49-line churn diff instead of a
one-line change. Correct instinct to fix it, wrong tool: I ran
`git checkout -- editorial/schedule.csv`, which reverts to HEAD, and
`schedule.csv` had uncommitted changes at session start. That destroyed the
rows the 2026-09-17, 2026-09-18 and 2026-09-21 runs had written for briefs 33,
34 and 35, dropping all three back to `not_started`.

Recovered within the same run. Status and all four dates for the three rows were
restored verbatim from the session-start snapshot, which was still in context,
and re-applied with `editorial/scripts/set-status.mjs`, the script that exists
precisely so nobody rewrites this file by hand. The original `notes` text is not
recoverable and was not invented: each of the three rows now carries a note that
says plainly the original was destroyed on 2026-09-22, points at that run's daily
log and run log, and restates only the facts those logs actually record. Brief
35's note keeps the one operational fact a publisher needs, that two competing
drafts exist and a person must pick which one ships.

Two lessons for the next run, stated so they are not repeated. Use
`set-status.mjs` for every `schedule.csv` change, never a CSV library and never
by hand. And never run `git checkout --` on a path in this repo: the working
tree carries uncommitted editorial state between runs by design, so a revert to
HEAD is a destructive operation here, not a cleanup.
